# hypr2d design

A Hyprland plugin giving every monitor its own 2D workspace grid, an overview
of all grids at once (with special workspaces) where windows can be dragged
anywhere including across monitors, a finger-tracking 2D trackpad swipe, a
waybar module, and a small extension API. Keep it straightforward and high
quality: small surface, well tested, no feature creep.

## Environment

- Hyprland **0.56** (the user's flake input: `github:hyprwm/Hyprland` at rev
  `e368c13c27a42a173b9e08fa0bf413f9f7073187`). Config is **Lua**
  (`~/.config/hypr/hyprland.lua`, generated by Home Manager with
  `configType = "lua"`); dispatchers use the `hl.dsp.*` form, e.g.
  `hyprctl dispatch 'hl.dsp.focus({ workspace = 23 })'`.
- NixOS + Home Manager. The user's HM repo: `~/Config/home-manager`
  (Hyprland config under `users/wolf/desktop/hyprland/`; current grid script
  `workspace2d.sh`, binds in `keybinds.nix`, gestures in `default.nix`).
- The plugin ABI is not stable: build against the exact Hyprland the user runs.
  The flake takes a `hyprland` input; the user's HM flake will set
  `inputs.hypr2d.inputs.hyprland.follows = "hyprland"`.

## Architecture

```
core/     Rust (lib + staticlib): grid model, numbering, moves, swipe physics,
          overview layout & hit-testing, drag state machine, protocol (serde).
          Pure logic, no Hyprland types, thoroughly unit-tested.
plugin/   C++: thin shim. Plugin entry, dispatcher/hyprctl registration,
          gesture & input hooks, render-pass elements for overview/swipe,
          workspace texture rendering. Calls core through `cxx`.
cli/      Rust: `hypr2d` CLI (state, waybar module, client of the socket).
client/   Rust crate `hypr2d-client` for the extension socket (M6).
nix/      flake parts: package (one .so linking the staticlib), HM module,
          `nix run .#nested` (nested Hyprland with a test config and the
          plugin preloaded), checks.
```

Rules:
- Logic lives in Rust; C++ only translates Hyprland state/events in and
  applies commands/draws out. Every bridge call is wrapped so a Rust panic can
  never unwind into Hyprland (catch_unwind → log + no-op).
- No polling anywhere. No `hyprctl` subprocesses from the plugin.
- Borrow ideas/code (MIT) from hyprexpo (overview rendering) and hyprkool
  (grid logic) with attribution where code is reused.

## Grid model

- **One grid per monitor.** Default 8×8, wrapping on. Configurable per
  monitor: columns, rows, wrap.
- **Numbering must match the user's current scheme** so nothing moves on
  switchover: `workspace = 10 * (y * 8 + x) + monitor_id + 1`
  (`max_screens = 10`, `matrix_size = 8`, x/y zero-based, monitor_id is
  Hyprland's monitor id). Make the formula configurable (stride, columns).
- Moves:
  - `move <dir>`: focused monitor goes to its neighbouring cell.
  - `move <dir> all`: every monitor moves one cell in that direction, each
    from its own current cell; focus returns to the originally focused monitor.
  - `carry <dir>`: move the active window to the neighbouring cell and follow.
  - `goto <x> <y> [monitor]`.
- Animation: horizontal moves slide horizontally, vertical moves slide
  vertically, decided per move by the plugin (today a script rewrites the
  `workspaces` animation style before each move; that hack goes away).
- Special workspaces are not part of the grid but are first-class in the
  overview and drag & drop.

## Binds

All of the user's current binds stay; only their targets change.

| Bind | Today | hypr2d |
|---|---|---|
| SUPER+CONTROL+H/J/K/L | `workspace2d left/down/up/right` | `hypr2d:move left/down/up/right` |
| SUPER+SHIFT+H/J/K/L | `workspace2d move_left/…` | `hypr2d:carry left/…` |
| SUPER+ALT+J | `workspace2d down all && toggle_special("")` | `hypr2d:move down all` then the same `toggle_special("")` |
| SUPER+ALT+K | `workspace2d up all && toggle_special("")` | `hypr2d:move up all` then `toggle_special("")` |
| 3-finger swipe (laptop) | `execGesture` → `workspace2d …` on completion (swipe up = `down`, natural) | tracked 2D swipe (M2), same natural direction |
| new: SUPER+TAB (suggested) | — | `hypr2d:overview` |

The script also runs `pkill -RTMIN+1 waybar` after moves to refresh a waybar
module; the hypr2d waybar module streams instead, so that goes away.

## Tracked swipe (M2)

Begin: lock axis after a few px. Update: render current + neighbour workspace
offset 1:1 with finger travel (same mechanism as Hyprland's own workspace
swipe render offsets). End: commit if distance > threshold or velocity >
threshold in the swipe direction, else spring back; rubber-band resistance at
non-wrapping edges. Reversal mid-swipe just follows the fingers. Config:
fingers, thresholds, natural/inverted. Pure logic (axis lock, progress,
velocity estimate, commit/bounce, spring curve) in Rust with tests.

## Overview (M4/M5)

- Shows **all monitors' grids simultaneously**, one panel per monitor, panels
  arranged like the physical monitor layout, each panel the monitor's full
  grid with live workspace thumbnails; plus a strip of special workspaces
  (named via config or by their main app; empty ones dimmed/hidden; ones
  currently shown highlighted).
- Keyboard: hjkl/arrows within a grid, Tab/Shift-Tab across monitors and the
  specials strip, Enter to go, Esc to close. Mouse: click to go.
- Drag & drop: drag a window thumbnail to any cell of any monitor's grid, into
  or out of a special workspace, onto another window to swap, or (floating)
  to a precise spot. Ghost + target highlight, Esc cancels.
- Rendering follows hyprexpo's approach (render workspaces to framebuffers on
  open, then compose); include special workspaces, which hyprexpo skips.
  Layout and hit-testing math live in Rust.

## Waybar (M3)

`hypr2d waybar [--monitor NAME]` is a waybar `custom` module with
`"return-type": "json"` that prints one JSON line per change (subscribe to
socket2 / the extension socket; never poll). Text: a compact minimap around
the current cell (configurable radius, e.g. 3×3) using glyphs for current /
occupied / empty / urgent; classes for styling; tooltip listing each occupied
cell's windows; on-click / on-scroll call the CLI to move. Must look good
with the user's OneDark Extra Dark bar (black background).

## Extension API (M6)

Three layers, no agent-specific code in this repo:
1. Dispatchers / `hyprctl hypr2d …` for binds and scripts.
2. socket2 events: `hypr2d>>cell>>MONITOR,X,Y`, `hypr2d>>overview>>open|close`,
   `hypr2d>>drop>>…`.
3. `$XDG_RUNTIME_DIR/hypr/$HYPRLAND_INSTANCE_SIGNATURE/hypr2d.sock`: versioned
   JSON lines. Annotations (label, badge, dot, colour, tooltip) on cells,
   specials, windows; reserved regions (e.g. "row 7 = agents", titled band in
   the overview, optionally skipped by moves); placement ("window W to cell");
   subscriptions to activate/drop on owned regions. Everything a client sets is
   dropped when its connection closes. Schema documented and versioned;
   `hypr2d-client` crate wraps it.

## Testing

- `cargo test` for core (the bulk of coverage).
- `nix run .#nested`: nested Hyprland (same build the plugin targets) with a
  test config and the plugin preloaded; reload via `hyprctl -i N plugin
  unload/load`. Never load an untested build into the user's live session.
- CI (GitHub Actions + `nix flake check`): build against the pinned Hyprland,
  core tests, clippy `-D warnings`, rustfmt, clang-format, and a headless or
  nested integration test that drives dispatchers via hyprctl and asserts the
  resulting workspace ids. Also a non-blocking job against Hyprland main to
  catch ABI breaks early.
